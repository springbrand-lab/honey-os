# HoneyOS 伴侣网页改版设计

日期：2026-08-08  
状态：待产品确认

## 1. 目标

将现有本地网页从基础聊天壳改造成私人 AI 伴侣的完整聊天入口，同时解决长任务期间无反馈、工具调用不可见、技术过程过于出戏的问题。

这次改版不照搬 Claude、ChatGPT 或 Agent 控制台。它参考 AI Elements、assistant-ui、CopilotKit 和 AG-UI 的事件生命周期与组件边界，但使用 HoneyOS 自己的关系语言、视觉系统和安全投影。

## 2. 产品原则

1. 第一感受是一个人在场，不是一个系统待命。
2. 用户必须知道对方仍在回应，但不需要看到模型的原始思维链。
3. 行动过程使用关系化语言，且必须符合当前伴侣人格。
4. 技术工具名、命令、路径、密钥、参数和原始结果不进入伴侣聊天界面。
5. 网页和飞书继续共享同一段对话、记忆与伴侣身份。
6. 快速回应不制造多余过程卡；较慢回应必须尽快给出在场反馈。

## 3. 视觉方向

### 3.1 设计判断

页面类型：桌面优先的私人伴侣聊天入口。  
目标用户：不需要理解 Agent、模型或工具的普通用户。  
视觉语言：私密、安静、有生命感，不做客服窗口或工作台。  
实现基础：现阶段使用原生 HTML、CSS 和 JavaScript，避免为单页引入完整 React 构建链。

设计参数：

- 变化度：6。桌面布局有空间感，但聊天主线仍容易理解。
- 动效：5。动效只表达在场、状态变化和消息到达。
- 信息密度：3。优先关系氛围和阅读舒适度。

### 3.2 页面构图

- 页面占满桌面窗口，不再把聊天压进一张悬浮的 460px 手机卡。
- 对话主列保持适合阅读的宽度，周围空间用于营造安静感，不放功能面板。
- 顶部仅展示伴侣头像、名字和自然状态，不放模型、网络或调试状态。
- 伴侣回复以接近自然文字的形式出现，弱化机器人白色气泡。
- 用户消息保留轻量气泡，明确区分说话双方。
- 输入区固定在底部，像私人聊天的消息托盘，不像表单。
- 同时支持浅色和深色主题，跟随系统偏好。

### 3.3 视觉系统

- 使用冷灰与柔和莓红作为单一强调色，避免 AI 紫色和大面积廉价渐变。
- 统一使用中等柔和圆角；消息、行动过程和输入框遵循同一形状规则。
- 头像在没有用户上传图片时使用有质感的名字首字，而不是通用机器人图标。
- 只在背景和输入托盘使用轻微材质感，聊天内容保持清楚。
- 所有文字达到 WCAG AA 对比度。

## 4. 对话组件

### 4.1 Conversation

负责历史消息、流式消息、自动滚动和回到底部按钮。用户主动向上阅读历史时，新内容不得强行把视图拉回底部。

### 4.2 Message

支持用户消息、伴侣消息和流式更新。第一版继续安全显示纯文本，后续可以独立增加经过清洗的 Markdown 渲染，不把 HTML 直接注入页面。

### 4.3 PresenceLine

每次发送后立即出现轻量在场状态，例如：

- 我在想你刚才说的事
- 我再想清楚一点
- 等我一下，我还在这里

它只表达可感知状态，不展示模型的原始 reasoning 内容。

### 4.4 ActionTrail

同一轮内的连续工具调用合并为一条行动轨迹。默认只显示当前动作，完成后折叠成一句摘要，避免刷出多张技术卡。

动作类型与默认关系语言：

| 类型 | 进行中 | 完成 |
| --- | --- | --- |
| 核对信息 | 我去替你认真看看 | 找到了，我整理一下 |
| 阅读内容 | 我在认真看你发来的内容 | 我看完了 |
| 制作内容 | 我来把它做好 | 好了，给你看看 |
| 记录提醒 | 我替你记下来 | 记住了，我不会漏掉 |
| 操作处理 | 我来处理一下 | 已经替你弄好了 |

这些文案是安全默认值。若伴侣已经形成明确人格，后端投影层可以在不暴露技术信息的前提下调整语气。前端只消费已经安全化的展示文本。

### 4.5 ResultCard

第一版只定义扩展接口，不实现大量卡片。后续按工具类型增加天气、地图、提醒、待办和文件结果卡。未知工具永远回退到 ActionTrail，不显示原始 JSON。

### 4.6 Composer

支持自动增高、Enter 发送、Shift+Enter 换行、发送中禁用重复提交以及明确的错误恢复。第一版不加入模型选择器、Token 统计或开发者工具。

## 5. 事件模型

前端不再直接围绕某一张临时 DOM 卡片更新，而是维护一轮有明确状态的运行对象：

```text
idle
  -> present
  -> acting
  -> responding
  -> completed

任意运行态
  -> failed
```

事件映射：

| 后端事件 | 前端行为 |
| --- | --- |
| `run.started` | 立即进入 `present`，显示 PresenceLine |
| `reasoning.available` | 只延续或更新安全状态，不传输原始思维链 |
| `tool.started` | 进入 `acting`，追加或更新 ActionTrail 项 |
| `tool.completed` | 标记动作完成，保留短暂可见状态 |
| `tool.failed` | 显示柔和失败状态，允许后续动作继续覆盖 |
| `assistant.delta` | 进入 `responding`，折叠 PresenceLine 和 ActionTrail，开始流式文字 |
| `assistant.completed` | 完成消息并结束本轮 |
| `error` | 进入 `failed`，显示可重试提示 |

工具事件必须携带稳定的 `activity_id`，用于区分同一轮中的多个工具。安全投影仅包含：

```json
{
  "activity_id": "activity_xxx",
  "kind": "checking",
  "state": "active",
  "title": "我去替你认真看看",
  "detail": ""
}
```

原始工具名、参数、查询内容和结果只保留在本地网关日志中。

## 6. 显示时序

- 发送后 150ms 内显示 PresenceLine，避免用户感觉页面卡死。
- 工具开始时立即切换为 ActionTrail，不再统一等待 1.2 秒。
- 如果整轮在约 500ms 内直接进入文字输出，可以跳过过程显示，避免闪烁。
- 工具完成后不立即删除状态，至少保留到下一状态到达，再平滑折叠。
- 同一轮连续动作复用同一个 ActionTrail 容器。
- 所有动效只改变透明度和位移，并遵循 `prefers-reduced-motion`。

## 7. 错误处理

### 7.1 模型未配置

网页显示可操作的首次配置提示，不把英文运行时错误作为伴侣回复。提示提供一个明确动作，引导用户运行 HoneyOS 配置流程。

### 7.2 Provider 失败

聊天区显示：“刚才没有连上。你可以再发一次，我也会在这里。”同时保留重试按钮。原始 Provider 错误仅进入日志。

### 7.3 工具失败

ActionTrail 显示：“刚才没走通，我换个办法。”如果 Agent 随后继续调用其他工具，状态可以恢复为进行中，不把整轮提前判定失败。

### 7.4 页面从文件打开

静态资源改为相对路径。若浏览器允许脚本，自动跳转到本地服务地址；若不允许跳转，页面仍能正确加载样式并显示“请启动 HoneyOS 后打开本地聊天”的明确提示，不再出现裸 HTML。

## 8. 技术边界

第一版不直接安装 AI Elements、assistant-ui 或 CopilotKit，原因如下：

- 当前网页是 Python 网关提供的本地静态页面，引入这些库需要新增 React 构建链。
- HoneyOS 已有自己的会话、记忆、SSE 和工具运行时，不应为了 UI 替换后端架构。
- 当前需求可以通过明确的事件状态机和小型原生组件完成。

本次会借用这些库的成熟概念：Conversation、Message Parts、Tool Group、Tool Status、Error Recovery 和 Custom Renderer。未来出现附件、语音、丰富交互卡片或多会话管理时，再评估迁移到 React 与 assistant-ui External Store Runtime。

## 9. 验收标准

### 9.1 视觉

- 桌面窗口中不再出现窄手机卡悬浮在大渐变背景上的效果。
- 正确加载与直接打开 HTML 两种情况都不会显示无样式裸页面。
- 浅色和深色模式都具备清楚层级与可读性。
- 页面中没有模型名、Token、工具名、命令或开发者日志。

### 9.2 行为

- 发送普通聊天后，150ms 内出现反馈或开始输出。
- 触发一次网页搜索时，能看到从在场状态到行动状态再到正式回复的完整转换。
- 连续触发三个工具时，只出现一个行动轨迹容器。
- 工具快速完成时不会完全无反馈，也不会闪出多张卡片。
- 工具失败后 Agent 可以继续尝试，页面状态不会卡死。
- Provider 未配置时显示中文配置引导。
- 网页和飞书继续读取同一会话历史。

### 9.3 测试

- 单元测试覆盖事件到 UI 状态的映射、活动合并、失败恢复和安全字段过滤。
- API 测试覆盖 `activity_id`、Reasoning 安全投影和 SSE 顺序。
- 浏览器级验收覆盖流式文字、滚动锁定、输入行为、浅色、深色与减少动效。
- 保留现有会话共享、Cookie 鉴权、CSP 与本地回环地址测试。

## 10. 本次不做

- 展示原始思维链。
- 显示终端命令、文件路径、请求参数或完整工具结果。
- 账号系统与云端同步。
- 手机远程访问。
- 大量 Generative UI 卡片。
- 把飞书的工具过程同步展示出来。
