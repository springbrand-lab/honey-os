# HoneyOS 本机项目空间设计

日期：2026-08-08  
状态：已由产品确认，进入实现

## 目标

HoneyOS 的 Coding 产物必须直接出现在用户电脑上，可以用 Finder、编辑器和浏览器打开。普通开发命令不再依赖 Docker，也不要求逐次确认；伴侣记忆、渠道配置和已有数据必须原样保留。

## 用户体验

- 默认项目根目录为 `~/HoneyOS Projects`。
- 每个游戏、网页或代码任务使用该根目录下的独立子目录。
- 终端、代码执行和文件工具共享当前项目目录。
- 完成项目后，回复给出项目真实路径；网页项目可以启动仅监听 `127.0.0.1` 的本地预览。
- 用户明确指定根目录以外的现有项目时，后续版本可提供单目录授权；本版不默认扩大访问范围。

## 执行与安全边界

- 默认终端后端改为本机 `local`，工作目录为项目根目录。
- 普通项目内命令直接运行，包括 Git、Python、Node、构建、测试和项目级依赖安装。
- 危险命令审批从 `off` 改为 `manual`：只有已有危险模式命中的命令才向用户确认；不可恢复的系统破坏仍无条件阻止。
- 文件写入必须位于项目根目录或 HoneyOS 自身受管数据目录；敏感系统路径继续拒绝。
- 项目进程不继承 HoneyOS 模型、IM、代理等内部密钥。
- 本机模式是产品级工作区边界，不宣称具备 Docker/虚拟机同等级别的操作系统隔离。

## 数据与升级

- `~/.honeyos` 中的 `SOUL.md`、`memories/`、`sessions/`、`skills/`、待办、定时任务、模型和 IM 配置均不迁移、不覆盖。
- 首次升级创建 `~/HoneyOS Projects`。
- 旧 Docker 持久工作区实际位于 `~/.honeyos/sandboxes/docker/*/workspace` 和 `*/home`。
- 升级时将旧 `workspace` 内容和旧 `home` 下的非隐藏用户文件复制到 `~/HoneyOS Projects/从旧版本恢复/<任务>/`。
- 恢复是幂等的：写入完成标记后不重复复制；冲突时不覆盖已有文件。
- 不删除旧 Docker 文件、容器或目录。恢复失败只产生诊断提醒，不阻止聊天和新项目使用。

## 配置与诊断

- 新安装和升级后的受管配置使用本机后端及项目根目录。
- `honeyos doctor` 将检查本机项目根目录存在、可写、终端后端为 `local`、危险命令审批不为 `off`。
- Docker 缺失不再作为 Coding 能力不可用的警告；Docker 仅保留为高级用户主动配置的可选后端。
- System Prompt 明确终端运行在用户本机的 HoneyOS 项目空间，要求把可交付文件放在真实项目目录中。

## 验收标准

1. 全新用户初始化后得到可写的 `~/HoneyOS Projects`，配置为本机终端。
2. 旧用户升级后记忆与配置内容保持，只有受管执行策略字段更新。
3. Agent 创建的文件可直接由宿主机读取。
4. 普通项目命令不触发确认，危险命令仍进入审批或硬阻止。
5. 旧 Docker 工作区可恢复且原数据不被删除。
6. 没有安装 Docker 的电脑仍通过首次启动检查并具备 Coding 能力。
7. README 说明本机项目目录、能力范围与安全边界。

## 非目标

- 本版不实现任意目录的图形化授权选择器。
- 本版不实现 Unity、Godot、Xcode 等桌面编辑器自动操作。
- 本版不删除 Docker 支持，也不自动卸载用户的 Docker。
- 本版不提供与容器等价的恶意代码强隔离保证。
