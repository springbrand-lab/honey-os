# HoneyOS Claude 式组件重设计

## 目标

在不改变 HoneyOS 现有暖色品牌和后端能力的前提下，重做网页端组件系统。界面参考 Claude 的克制排版、留白和交互完成度，但保留 AI 伴侣需要的关系感、双方身份和工具过程表达。

本次解决的是头像、消息、工具状态、输入框、导航和页面组件粗糙的问题，不是再次更换配色。

## 视觉原则

- 保留现有暖中性色和单一橙色强调色。
- 助手回复采用无大气泡的阅读排版；用户消息使用紧凑、浅色气泡。
- 通过字号、字重、间距和分隔线建立层级，避免到处使用白色卡片。
- 组件圆角遵循统一规则：普通组件 10–12px，消息气泡 14–16px，圆形头像和图标按钮除外。
- 图标统一使用 Phosphor，同一粗细，不再使用 `◌`、`◇`、`⌁` 等字符充当图标。
- 动效只表达新消息、展开、状态变化和按钮反馈，并支持减少动态效果。

## 头像

- 默认头像使用稳定的字母头像，不使用随机生成的人脸。
- 伴侣头像从伴侣名称中取首个有效字符；用户默认显示“你”。
- 字母头像使用低饱和纯色或极轻微质感，带 1px 内描边，不使用高亮渐变和重阴影。
- 数据接口为以后上传头像或选择内置简笔画保留 `avatar_url` 与 fallback，不在本次增加上传流程。
- 顶部头像为 38px，消息头像为 30px，所有位置共享同一头像组件和取值逻辑。

## 核心组件

### 导航与顶部栏

- 侧栏宽度更紧凑，导航项使用统一图标、文本和选中态。
- 顶部只保留伴侣头像、名称、在线状态、最近看到的和聊天记录入口。
- “最近看到的”改为低干扰图标操作；存在未读内容时再显示计数。

### 消息

- 助手消息按头像、正文、悬浮操作三层组成，正文最大宽度约 760–820px。
- 用户消息右对齐，最大宽度约 72%，保持短消息紧凑。
- Markdown 统一处理标题、列表、引用、链接、代码块和表格；不显示原始 `**` 标记。
- 复制、重试、反馈操作默认隐藏，在悬浮或键盘聚焦时出现。

### 工具与处理状态

- 工具过程合并为一个可展开的状态卡，不连续渲染多个相同文案。
- 收起状态显示人格化标题、当前状态和展开按钮。
- 展开状态显示自然语言步骤、耗时与必要结果；不直接暴露内部思考或原始日志。
- 进行中、成功、失败和等待用户允许使用同一组件的不同状态。

### 输入框

- 使用浮动的自动增高输入框，附件入口在左，发送或停止按钮在右。
- 聚焦通过边框和低强度外环表达，不使用大面积高亮。
- 移动端保持输入框与安全区域距离，按钮不挤压正文。

### 记忆、我们、历史和设置

- 共用同一套页面标题、标签、列表、空状态、表单和按钮组件。
- 不再让聊天页精致而次级页面保留旧样式。

## 前端架构

- 将网页端迁为 React + Vite，并使用 Tailwind CSS 与选取后的 AI Elements/shadcn primitives。
- 保留现有 Python HTTP、SSE、记忆、权限、话题池和文件打开接口，不改数据目录。
- 构建后的静态资源随 HoneyOS 分发；最终用户不需要 Node.js，也不需要单独启动前端开发服务。
- 将组件拆分为 AppShell、Avatar、Message、MarkdownContent、ToolActivity、Composer、MemoryView、RelationshipView、HistoryView、SettingsView。
- 保留旧静态前端作为迁移期间的可回退构建，完成接口和功能对照后再删除。

## 状态与错误

- 覆盖加载、空白、流式回复、工具执行、等待允许、错误和断线重连状态。
- 错误使用聊天内的自然语言提示；技术细节仅在展开区或日志里显示。
- 如果头像或配置字段缺失，稳定回退到字母头像，不显示破图。

## 验收标准

- 双方头像在顶部、聊天、工具状态和关系页保持一致。
- 普通消息、长 Markdown、列表、代码、工具调用和审批不会破坏布局。
- 桌面宽屏、1024px、768px 和手机宽度均可使用。
- 网页与飞书继续共享同一段聊天、记忆和运行状态。
- 原有聊天、记忆、人格、模型和渠道配置不被迁移或清空。
- 前端测试覆盖消息渲染、工具状态、头像回退和主要页面导航；构建产物可由现有 HoneyOS 服务直接托管。
