# HoneyOS 本地伴侣聊天页 PRD v0.1

## 目标

为不想配置微信或飞书的普通用户提供开箱即用的电脑聊天入口，同时解决 Agent 长任务“像卡死”和展示原始工具日志“太出戏”的冲突。

网页、微信和飞书不是三个机器人，而是同一个本地伴侣的三个入口：共享短期会话、长期记忆、身份与关系状态。

## 本期范围

- 只支持安装 HoneyOS 的这台电脑，不做账号、云同步和远程访问。
- 安装完成后网页入口默认可用，微信与飞书都变成可选项。
- 提供单列、模拟私人聊天的页面，不采用开发工具或工作台布局。
- 页面展示用户消息、伴侣回复和经过语义化处理的过程卡片。
- 保留现有 Agent Runtime、工具、Skill、记忆和定时任务能力。

## 体验原则

1. 先像一段关系，再像一个产品。页面不展示模型名、Token、工具名、命令行或推理过程。
2. 短任务不打扰。任务在 1.2 秒内完成时，不展示过程卡片。
3. 长任务有回应。超过阈值后，只保留一张会更新状态的卡片，例如“正在认真核对”“正在替你处理”。
4. 最终回复仍由当前伴侣人格生成。卡片只承担等待反馈，不代替关系动作或最终表达。
5. 原始执行细节只进入本地日志。发送到页面的活动对象不包含查询词、命令、参数、路径或密钥。

## 会话与记忆

- 在单用户伴侣运行模式下，网页、微信和飞书私聊映射到同一个 owner 会话键。
- 用户从网页切到飞书时，可以继续看到并延续同一段上下文；长期记忆继续由现有记忆系统维护。
- 非伴侣运行模式和群聊不做会话合并，避免影响通用 Runtime 行为。
- `/new` 只开启新的短期上下文，不删除 `IDENTITY.md`、`RELATIONSHIP.md` 和其他长期记忆。

## 活动卡片协议

Runtime 保留完整工具事件用于调试；伴侣页面只消费安全投影：

```json
{
  "kind": "checking",
  "state": "active",
  "title": "正在认真核对",
  "detail": "我在看几处相关内容"
}
```

`kind` 只允许 `checking`、`reading`、`making`、`remembering`、`handling`；`state` 只允许 `active`、`completed`、`failed`。文案可以根据当前伴侣人设继续迭代，但不得暴露原始工具字段。

## 本地安全

- Web 服务默认只绑定 `127.0.0.1:8642`。
- 首次初始化生成独立随机密钥，保存在用户本地 `.env`，不写入仓库。
- 浏览器通过仅本机可获得的 HttpOnly、SameSite=Strict Cookie 访问聊天接口。
- 页面使用严格 CSP；消息按纯文本写入 DOM，避免记忆或模型输出注入脚本。
- 跨域请求默认拒绝；既有 API Bearer Key 方式保持兼容。

## 启动链路

1. 首次安装：填写 Base URL、Model ID、API Key。
2. 用户可选择配置微信/飞书，也可选择“暂时只用网页”。
3. 后台服务启动并完成模型、本地目录和聊天入口检查。
4. 浏览器打开 `http://127.0.0.1:8642/`，加载同一个 owner 会话。
5. 后续执行 `honeyos web` 会确保后台服务已启动并重新打开聊天页。

## 验收标准

- 没有微信、飞书账号也能完成安装并在网页发送消息。
- 同一个用户从网页和飞书发送消息时，伴侣可延续上下文和记忆。
- 长工具任务能看到克制的过程反馈，页面不出现英文工具名、命令、原始参数和思考文本。
- 关闭并重开浏览器后，历史消息仍可恢复。
- 非本机来源不能访问聊天页面；任意模型输出不能作为 HTML 执行。
